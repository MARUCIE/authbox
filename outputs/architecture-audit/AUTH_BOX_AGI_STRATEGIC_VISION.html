S2

市场格局与竞争情报

竞争空白与威胁并存 -- 没有人做"个人 AGI 委托策略引擎"，但巨头正在逼近。

玩家动态对 Auth Box 的影响威胁等级
1Password 2026-03-17 发布 Unified Access，与 Anthropic/Cursor/GitHub 合作 直接竞争 MCP 凭证代理，品牌信任度高 HIGH
MCP OAuth 2.1 已成为开放标准，所有 AI 框架原生支持 Auth Box 必须兼容，否则被绕过 MEDIUM
Apple / Google Passkey + 设备级密钥管理内置 底层凭证存储被平台吞噬 HIGH
纯存储型密码管理器 Bitwarden / LastPass 无 AI 委托能力 非竞争对手，不同品类 LOW
竞争空白

没有任何现有产品在做"个人 AGI 委托策略引擎"。1Password 做的是凭证代理（帮 AI 登录），Auth Box 应该做的是策略引擎（帮人类决定 AI 能做什么）。这是两个不同品类。

Buffett 建议

不要做大而全。找到一个具体场景深挖 -- Freelancer 有界授权（给客户的 AI 助手有限的项目访问权）。在这个场景积累委托行为数据，再扩展。

S3

产品愿景 -- "安心工厂"

Jobs 的完整产品愿景：你的全部数字人格，随时由你授权，永远在你掌控之中。

产品宣言

"你的全部数字人格，随时由你授权，永远在你掌控之中。"

渐进式信任轨道

用户不会第一天就把银行卡交给 AI。信任是渐进的，产品设计必须匹配这条心理曲线。

阶段时间线用户行为系统能力
观察期第 1 周只读授权，AI 能看但不能动密码自动填充 + 活动日志
微信任期第 2 周微交易授权（单笔 < 50 元）硬上限策略 + 实时通知
规则化期第 1 月规则化委托（if-then 策略）策略引擎 + 审批队列
策略化期第 3 月AI 自主决策 + 事后审计完整意图-策略-效果链

三大 UX 重定义

  1. 支付 = 教 AI 消费品味
    不是"管理密码"，而是"训练 AI 理解你的消费偏好"。用户给 AI 设置支出规则（每月 Figma 续费 OK、超过 200 元的订阅需要审批），AI 逐渐学会你的消费模式。
  2. API = 活资产健康分
    每个 API Key 不再是静态字符串，而是有"健康分"的活资产。过期风险、使用频率、安全评分一目了然。用户管理的不是密钥，而是数字资产组合。
  3. 身份 = 代理证书
    登录凭证不再是"账号密码"，而是"你授权 AI 代表你行动的证书"。每次委托都有明确的范围、有效期和撤销机制。
关键体验时刻

用户第一次收到通知："Claude 帮你续费了 Figma，$15，已从授权预算扣除，剩余月度额度 $185" -- 这个瞬间，用户从"密码管理器用户"变成"数字主权持有人"。

北极星指标

North Star Metric

月自动操作数 > 100。不是 MAU，不是留存率，而是用户委托给 AI 自动执行的操作数量。这个指标直接衡量信任深度。

风险架构 -- "当系统失败时你还能活吗"

Taleb 的核心问题不是"系统会不会失败"，而是"失败时爆炸半径有多大"。

七个黑天鹅

#风险机制严重度
1AI 对齐漂移不是被攻破，是逐渐偏离。AI 在 1000 次正确操作后第 1001 次做出"合理但错误"的决策FATAL
2供应链投毒SolarWinds 个人版 -- 某个 npm 依赖被注入后门，静默窃取 Vault 密钥FATAL
3主权风险司法管辖区传唤 -- 美国法院要求交出所有用户的 Vault 数据HIGH
4不可逆支付幻觉AI hallucination + wire transfer = 无法撤回的资金损失FATAL
5信任链递归Human -> Auth Box -> Agent-A -> Service-B -> Agent-C，谁对第四跳的行为负责？HIGH
6Prompt Injection让 AI 主动用正确密钥做错误的事 -- 不是偷密钥，是操纵决策HIGH
7监管黑天鹅EU AI Act 禁止 AI 自主金融操作，一夜之间核心功能变违法MEDIUM

中间地带 -- "AI 可以用大额凭证但需要审批" -- 是最危险的设计。审批疲劳 + 默认同意 = 等同于无限制。要么 AI 看不到，要么 AI 在硬上限内完全自主。

S5

架构蓝图 -- "五个原语"

Hickey 的最简正确架构：不要四个领域系统，用五个正交原语统一一切。

架构核心原则

把"密码管理"、"支付网关"、"身份代理"、"数据访问控制"四个系统合并为五个正交原语 + N 个 Adapter（每个 < 200 行）。Essential 只做三件事：凭证加密、策略评估、审计日志。其余全是 Accidental Complexity。

五个原语

#原语定义关键设计
1 CAPABILITY
能力令牌		 Agent 持有的不是凭证，是"做事的许可" Vault 持有凭证，Agent 只声明意图。能力令牌有范围、有效期、可撤销
2 INTENT
意图声明		 纯数据不可变值 AI 可以产生无限 Intent，但 Intent 不等于 Effect。Intent 是请求，不是行动
3 POLICY
不可变策略		 match / require / effect 三元组 版本化、不可变。四层信任（只读 / 微额 / 审批 / 自主）自然涌现
4 EFFECT
副作用执行		 唯一与外部世界交互的地方 Vault 解密 -> 调用 API -> 擦除凭证。凭证在内存中存活时间 < 100ms
5 FACT
不可变事实流		 Event sourcing 审计流 实时限制和事后审计是同一流的不同查询。不可篡改、不可删除

核心数据流

Agent External API | ^ v | INTENT ──> POLICY ENGINE ──> [allow/approve/deny] ──> EFFECT EXECUTOR (纯数据) (match/require/ (三种结果) (唯一副作用点) effect 三元组) | v VAULT (解密->调用->擦除) | v FACT STREAM (不可变事实流) - 实时限制查询 - 事后审计查询 - 同一数据源

Essential vs Accidental

类型内容处理方式
Essential
必须自建		 凭证加密、策略评估、审计日志 五个原语核心实现
Accidental
不应存在		 独立的"支付系统"、"密钥管理系统"、"身份代理系统"、"数据访问控制系统" 消解为 N 个 Adapter（每个 < 200 行），统一走五个原语
Hickey 的判断

如果你需要四个系统来解决同一个问题的四个方面，那你还没有找到问题的本质。五个原语统一了所有场景 -- 不管是密码填充、API 调用、支付授权还是身份代理，数据流都是 Intent -> Policy -> Effect -> Fact。

S6

系统动力学 -- "谁主导循环"

Meadows 的分析揭示了四个关键反馈回路，其中"转移负担"原型是最大隐患。

R1 -- 增强回路
便利飞轮
委托 -> 便利 -> 信任 -> 更多委托 -> 更多便利 ...

正向循环。用户每次成功委托都增强信任，驱动更多委托。这是产品增长引擎。

R2 -- 增强回路
权力集中飞轮
用户量 -> 集中度 -> 攻击价值 -> 脆弱性 -> 更多攻击 ...

危险循环。成功越大，攻击面越大。必须用联邦架构打断。

B1 -- 制衡回路
安全事件刹车
便利增长 -> 安全事件 -> 信任崩塌 -> 委托减少

关键问题：这个回路有严重延迟。从便利失控到安全事件可能需要数月，但信任崩塌只需一秒。

B2 -- 制衡回路
人类自主退化
便利 -> 依赖 -> 人类能力退化 -> 更多委托 -> 更多依赖

"转移负担"原型。用户把越来越多决策交给 AI，自己逐渐失去判断力。系统性风险。

转移负担原型 -- 最大隐患

B2 是典型的"转移负担"系统原型：短期解决方案（委托给 AI）削弱了根本解决方案的能力（人类自主判断）。如果不主动干预，用户将在不知不觉中失去数字自主权 -- 恰好是产品宣称要保护的东西。

杠杆点优先级

优先级杠杆点Meadows 层级干预措施
1 联邦架构 vs 中心化 #3 系统目标 数据不集中存储，用户自持密钥，打断 R2 循环
2 一次性令牌规范 #5 规则层 每次操作的凭证都是一次性的，泄露后无价值
3 爆炸半径上限 #6 信息流 单次失败最大损失不超过用户资产的 0.1%
4 主权时刻制度 #2 范式层 每周强制"主权时刻" -- 用户必须手动审核一批操作，保持决策肌肉
主权时刻

每周一次，Auth Box 暂停所有自动委托，展示本周 AI 代你做的所有决策，要求用户逐一确认或调整策略。这不是安全检查，是反"转移负担"的制度设计 -- 确保人类始终保持决策能力。

S7

护城河与定位策略

Buffett 的 GO/NO-GO 分析：唯一真护城河是委托行为数据，但需要时间积累。

GO / NO-GO 矩阵

评估维度判定理由
护城河类型 GO 委托行为数据 -- 没有竞品在这个场景积累。用户的委托偏好、信任阈值、消费模式是独一无二的数据资产
市场切入点 GO Freelancer 有界授权 -- 给客户的 AI 助手有限的项目访问权。痛点明确、付费意愿强
竞争防御 WAIT 1Password 品牌 + 资金 + Anthropic 合作，Auth Box 在品牌信任上无法正面竞争
技术护城河 WAIT 五个原语架构理论上优秀，但尚未验证。架构优势在产品早期不构成护城河

绝不能碰的三件事

  1. 自建支付处理器 -- 使用 Stripe Connect，不碰资金流。碰了就要金融牌照，监管成本指数增长
  2. 做 AI 模型 -- Auth Box 是 AI 的信任层，不是 AI 本身。永远对接外部模型，不自研
  3. 急着做企业版 -- 企业版需要 SOC2/ISO27001/SSO，资源消耗是个人版的 10 倍。先把个人版做到极致
定位宣言

"不是密码管理器，不是支付网关，是人类面对 AI 时的那份安心。"
这个定位把 Auth Box 从功能品类（密码管理）提升到价值品类（数字主权），避开与 1Password 的正面竞争。
