02

P0 阻断问题 (4 项)

以下 4 个问题均为阻断性缺陷，必须在任何功能迭代之前修复。每个问题都会直接导致核心功能失效或安全机制失守。

P0-1 CRITICAL -- SRP M1 客户端/服务端不一致

现象：SRP-6a 认证流程中，客户端与服务端对 M1 证明值的计算方式不一致。

定位：

  • 客户端 srp.ts:207: M1 = H(A | B | K)，其中 K = H(S)
  • 服务端 srp.go:111: 期望 M1 = H(A | B | S)

影响：登录流程完全无法工作，认证握手必然失败。

修复：统一为 M1 = H(A | B | K) 标准，K = H(S)。这是 RFC 5054 推荐的做法。

P0-2 CRITICAL -- TOTP 2FA 未集成到登录流程

现象：LoginVerify 方法未检查 user.TOTPEnabled 字段，启用 2FA 的用户可以绕过验证直接登录。

影响：二因素认证形同虚设，安全等级降级为纯密码认证。

修复：在 auth_service.go 的 LoginVerify 方法中，SRP 验证通过后、签发 JWT 之前，添加 TOTP 检查逻辑。若用户已启用 TOTP，返回中间状态要求客户端提交验证码。

P0-3 CRITICAL -- 零测试覆盖

现象：整个 Go 后端没有任何 _test.go 文件。

影响：无法验证任何代码修改的正确性，回归风险极高。上述 SRP 修复若无测试保护，可能引入新问题。

修复：优先覆盖三个核心路径 -- SRP 握手全流程、Vault CRUD 操作、Auth middleware 鉴权逻辑。目标覆盖率 ≥ 70%。

P0-4 CRITICAL -- Service 层硬编码仓库类型

现象：Service 层直接引用 *pg.UserRepository 具体实现而非接口。

影响：无法编写单元测试（无法注入 mock 仓库），无法替换数据库实现。DDD 的 Repository 模式形同虚设。

修复：在 domain 层定义 UserRepository、VaultRepository 等接口，Service 层仅依赖接口。

03

P1 代码质量问题 (4 项)

P1 问题不会导致功能失效，但会增加维护成本、降低代码健壮性，建议在 Phase B 中统一修复。

P1-1 -- 错误字符串匹配

位置：auth_handler.go:51

当前使用字符串比较判断错误类型，脆弱且不可维护。应定义 sentinel errors 并使用 errors.Is() 进行类型安全的错误匹配。

P1-2 -- Content-Type 验证跳过 DELETE

位置：security.go:32

安全中间件仅对 GET/HEAD 跳过 Content-Type 验证，遗漏了 OPTIONS 预检请求，同时错误地跳过了 DELETE 请求的验证。应仅跳过 GET/HEAD/OPTIONS。

P1-3 -- Base64 解码重复 11 次

位置：connection_service.go:114-149

同一个 base64 解码+错误处理模式在文件中重复出现 11 次。应抽离为 decodeB64Field(name, value string) ([]byte, error) 工具函数。

P1-4 -- 不安全类型转换

位置：passwords/page.tsx:203

前端使用 as any 进行类型断言，丢失了 TypeScript 的类型安全保护。应定义 VaultItemData 共享类型，在前后端间保持一致。

核心设计原则

PRINCIPLE 01

No-Line Rule

用色彩层次替代传统边框线。通过 surface 色阶差异创建视觉分隔，减少界面噪音。

PRINCIPLE 02

Ghost Border

仅在无障碍需要时使用 20% opacity 边框。所有视觉分隔优先依赖色彩对比而非线条。

PRINCIPLE 03

Security Ceremony

加密过程可视化，让安全感看得见。每一次解锁、同步、加密操作都有对应的动效仪式。

PRINCIPLE 04

Tonal Layering

通过 surface 层级创建深度感，取代传统 box-shadow。层级越高，色彩越亮。

07

设计实施建议

基于 Vault Onyx 设计系统和 Stitch 原型，提出以下实施建议：

  1. 将 Vault Onyx 设计系统固化为 Tailwind CSS preset
    在 tailwind.config.ts 中定义 colors / spacing / typography / borderRadius 等 design tokens，确保设计系统与代码实现的单一真相源。

  2. 基于 shadcn/ui 扩展组件库
    当前组件库仅有 3 个 UI 组件 + 5 个业务组件，严重不足。需补齐 Tooltip / Dropdown / Toast / Skeleton / Tabs / Dialog / Sheet 等基础组件。

  3. 统一两个 App 的样式基础
    web 和 console 两个 App 的 globals.css + layout.tsx 结构完全割裂。应抽离共享 packages/ui，统一主题/布局/组件。

  4. 将 Stitch 原型转为 React 组件
    10 个 Stitch 页面作为视觉参考，按 Phase C 计划逐步转化为 React 组件。优先转化高频页面：Passwords Vault / Login / AI Agents。

  5. 3 轮 UI polish 迭代
    每次 UI/UX 打磨必须做满 3 轮迭代。第 1 轮结构还原，第 2 轮细节打磨 (间距/色彩/动效)，第 3 轮无障碍+响应式验证。
