01 — 决策

StoreKit 2 直连，一次性非消耗品

苹果强制要求：解锁数字功能必须走 In-App Purchase（IAP，应用内购买）；对同一项权益用 Stripe（支付平台）刷卡会在 App Review（应用审核）被拒。RevenueCat（内购聚合 SaaS）是 StoreKit 之上的封装层，并非替代方案——它为单一一次性商品额外引入了服务端依赖与厂商抽成，而我们并不需要。因此 App 直接与 StoreKit 2 对话。

03 — 授权流

unlock() 是所有 StoreKit 路径的唯一汇聚点

购买、后台交易更新、启动时校验、恢复购买——四条路径最终都汇聚到同一个 unlock()。验证是严格的：只有 VerificationResult.verified 分支才解锁，.unverified 直接抛错。

启动 ProManager.init(): isPro = UserDefaults["authbox_pro_unlocked"] // 缓存读取 Task { loadProduct(); verifyEntitlement() } 付费墙点击 → ProManager.purchase() ├─ loadProduct() → Product.products(for: ["com.authbox.pro"]) ├─ product.purchase() → StoreKit 购买弹窗（苹果） ├─ checkVerified(result) → 仅 .verified 分支 ├─ transaction.finish() └─ unlock() ───────────────┐ │ 后台 Transaction.updates ──────┤→ unlock() // 带外购买 / 续期 启动 Transaction.currentEntitlements ─┤→ unlock() // verifyEntitlement 恢复 AppStore.sync() → verifyEntitlement() ┘ unlock(): isPro = true ; UserDefaults["authbox_pro_unlocked"] = true → 每个 canUseFeature(.pro*) 返回 true → 缓存让授权熬过下次冷启动

04 — 测试策略

两半分开验证：App 拥有的一半，苹果拥有的一半

支付系统天然分为「App 负责的授权逻辑」与「苹果负责的 StoreKit 往返」。两者独立验证，互不掩盖。

始终运行 授权逻辑（App 的一半）

驱动真实的 ProManager 方法（无 stub，无桩），断言整套系统：

  • testFreeTierGating — 免费/Pro 矩阵与付费墙一致
  • testUnlockFlipsEntireSystem — 调用真实 unlock() 后 isPro 翻转、六项 Pro 全开、缓存标记按 init() 读取的同一键持久化
  • testCachedEntitlementSurvivesRelaunch — 已购用户冷启动后凭本地缓存仍为 Pro，无需重连 StoreKit

回归下跳过 StoreKit 往返（苹果的一半）

完整跑通 API：Product.products → purchase() → currentEntitlements → unlock()。

  • testRealStoreKitPurchaseUnlocksPro
  • testRealStoreKitRestoreReDetectsEntitlement

当运行时无法交付产品时，两者 XCTSkipIf跳过（而非失败）并注明回归原因；一旦环境能同步配置，它们立刻转为真实端到端证明。

05 — 已知阻塞

iOS 26.5 模拟器 + xcodebuild test 命令行

在公开的 iOS 26.5 模拟器运行时下，通过 xcodebuild test 命令行跑测试，不会把 .storekit 配置同步到模拟器的 StoreKit 守护进程。2026-06-03 在 Xcode 26.5（build 17F42）实测：

产品为空

Product.products(for:) 返回 count = 0，且不抛错。

购买被拒

SKTestSession.buyProduct 抛出 notEntitled。

非我方缺陷

.storekit 确已打包、SKTestSession 确已创建——配置只是没到达守护进程。

这是苹果工具链回归，不是配置或代码缺陷。Xcode IDE（Cmd+U）走的是内部 DVTDevice 同步路径，公开命令行并不触发该路径。这也解释了为何在排除了 UUID、配置版本号、bundle 路径、scheme 冲突等所有我方可控原因后，症状依旧——根因在外部环境。

如何跑真实 StoreKit 证明

路径做法
Xcode IDE打开 apps/ios/AuthBox.xcodeproj，按 Cmd+U。IDE 会同步配置，两个跳过的测试转为真实运行。
iOS 26.1 模拟器安装较旧运行时并指向它；该版本命令行同步可用。
真机沙盒用团队签名，在 App Store Connect 建好商品（或经 Run scheme 挂载 .storekit），用沙盒 Apple ID 购买。

Run scheme 在 LaunchAction 中保留对 Configuration.storekit 的引用，所以在 IDE 里手动 Run（Cmd+R）即可看到真实价格与可用的购买弹窗。
