01 — 目标

钱包是种子的新派生分支，而非外挂的密钥

把 Auth Box 从「零知识金库 + AI 密钥中枢（agent broker，代理密钥代办）」升级为同时也是一个自托管多币种加密钱包，先支持比特币与以太坊 / EVM（Ethereum Virtual Machine，以太坊虚拟机）。核心约束：不引入任何新的托管风险，不改变既有的零知识安全姿态。

02 — 核心洞察

种子本就是钱包种子

Auth Box 已经在保护一个 BIP-39 的 24 词助记词（packages/crypto/src/seed.ts）。其 mnemonicToSeed 完全符合 BIP-39 规范（PBKDF2-HMAC-SHA512，盐 "mnemonic"，2048 次迭代，64 字节输出）。因此用户手里已有的这串短语本身就是一个标准钱包种子 —— 加密钱包不是一个外挂的新秘密，而是用户已经掌控的那颗种子上的一条新派生分支。

03 — 密钥树

一个种子，两棵密码学独立的 HD 树

树HMAC 密钥派生方式用途互操作
Auth Box 内部树"authbox seed"自定义、仅硬化（deriveKey）金库 / 同步 / 代理 / 密码密钥无（刻意）
钱包树"Bitcoin seed"标准 BIP-32BTC / ETH 密钥完整（BIP-44/84）

两棵树虽共享同一颗种子，却因 HMAC 密钥不同而密码学独立（密钥材料完全不相交）。内部树保持自定义结构（其密钥是用于 AES/HKDF 的对称秘密，无需互操作）；钱包树保持标准，使同一串助记词能在 Electrum / MetaMask / Ledger 中恢复出完全相同的地址。「不锁定」是硬性要求 —— 这正是自托管的全部价值所在。

04 — 派生标准

双密码学体系，扩展即参数化

币种标准路径地址
BTC 原生隔离见证（默认）BIP-84m/84'/0'/0'/{change}/{i}bech32 bc1…（P2WPKH）
BTC 传统BIP-44m/44'/0'/0'/{change}/{i}base58 1…（P2PKH）

已实现的两个币种横跨两种密码学体系（UTXO/secp256k1+hash160 与账户/secp256k1+keccak）。新增 BTC 类币（LTC、DOGE）只是网络版本字节的改动；新增 EVM 链则复用同一个 ETH 地址不变。扩展是参数化，而非新的密码学。

05 — 安全模型

自托管 + watch-only 服务器

金库的零知识属性原样延伸到钱包：

私钥永不离开设备

私钥在客户端从种子派生，签名在本地完成，服务端从不接触密钥材料。

服务器只读观察

服务端只持久化账户级 xpub（扩展公钥）与派生地址 —— 够扫描余额与历史，永远不够花费。

服务器无法动资金

与金库同一信任边界：服务端被完全攻陷只泄露公开地址与余额（隐私损失），而非托管权。

威胁模型说明：从保护金库的同一颗种子派生钱包密钥，意味着种子一旦泄露，金库与资金同失。这是「单种子」模型的固有性质（与每一个硬件钱包完全相同），并未改变既有姿态 —— 种子本就是皇冠上的宝石，因为它早已派生出金库密钥。
06 — 库选择

不手搓曲线密码学

Web（packages/crypto，TypeScript）

关注点库理由
BIP-32 HD 派生@scure/bip32已审计；与在用的 @noble/hashes 同作者
secp256k1@noble/curves生态内的已审计参考实现
BTC 地址 / PSBT / 签名@scure/btc-signer正确的 bech32/base58check + selectUTXO 选币
ETH 交易构建 / EIP-1559 / 签名micro-eth-signerpaulmillr 出品、已审计、同 @noble/@scure 生态；免手搓 RLP
keccak256@noble/hashes/sha3已是依赖项

iOS（apps/ios/AuthBoxCrypto，Swift）

关注点库 / 实现理由
secp256k1swift-secp256k1 0.21（libsecp256k1 C 产物）同一个 libsecp256k1 参考 C 库；Swift 侧无曲线运算
SHA-256/512、HMACCryptoKit系统一方库、硬件加速
keccak256 / RIPEMD-160 / bech32 / base58check自带实现（各自对齐公开向量）CryptoKit 缺 Keccak 与 RIPEMD-160

手搓 secp256k1 的子密钥派生正是钱包染上 CVE 的地方（常量时间标量加、IL ≥ n 重试）。两个平台都把曲线运算委托给已审计的 libsecp256k1 血统；只有 BIP-39 短语逻辑与哈希/编码原语（纯位运算）是手写的，并对齐向量。

iOS 值得记录的坑：libsecp256k1 的静态 context 缺少 ecmult_gen 表，导致 pubkey_create 直接 abort —— 封装必须用 secp256k1_context_create(SECP256K1_CONTEXT_NONE) 创建 context；静态单例标注 nonisolated(unsafe) 以满足 Swift 6 并发。
07 — 跨平台一致性

打通契约：同一种子 → 同一地址

Web 与 iOS 从同一颗种子派生，必须产出完全相同的地址。Swift 栈（Wallet.swift）逐步镜像 TypeScript 栈（wallet.ts）：「Bitcoin seed」主密钥 → 硬化 + 非硬化 CKDpriv（childPriv = (IL + parentPriv) mod n，其中 IL = HMAC-SHA512(chainCode, 压缩父公钥 ‖ index)）→ BIP-84 P2WPKH / BIP-44 P2PKH / ETH EIP-55 → 账户 xpub。

一致性以公开的 all-zeros 助记词（abandon … about）的共享外部锚点来证明，两个平台逐字节产出：

币种路径地址

BTC 传统m/44'/0'/0'/0/01LqBGSKuX5yYUonjxT5qGfpUsXKYYWeabA

08 — 交易签名（Phase 5a · web · 无资金风险）

本地构建 + 签名，刻意不广播

packages/crypto/src/wallet-tx.ts 加入了客户端构建 + 签名（不广播）：

  • buildBtcTransaction —— 用 @scure/btc-signer 的 selectUTXO 选币 + 找零，P2WPKH 用 witnessUtxo / P2PKH 用 nonWitnessUtxo，逐输入「派生 → 签名 → 在 finally 中 fill(0) 清零私钥」。返回 { hex, txid, fee, vsize }；txid 为大端展示序。
  • buildEthTransaction —— 用 micro-eth-signer 的 Transaction.prepare({type:'eip1559'}).signBy(priv)。恢复出的 sender 被断言等于独立派生的地址（不匹配则抛错，而非交回一笔花费了意外密钥的交易）；私钥在 finally 中清零。
记录的发现：micro-eth-signer 的 ECDSA 是对冲式（hedged）的（在 RFC6979 nonce 上加额外熵 → 非确定但有效、且恢复出同一 sender），而 @scure/btc-signer 是确定性签名。测试因此按币种断言正确的不变量 —— ETH 断言「有效 + sender 可恢复」，BTC 断言「确定性」。密钥本地派生、用一次、清零；这里全程不触网。广播被刻意不实现 —— 那是 Phase 5b，须经 HITL（Human-In-The-Loop，人工在环）。
09 — 服务端

Go API（watch-only）

services/api 在 /wallet/accounts 下暴露只读观察的账户接口（chi 路由、pgx 仓储）。它存 xpub + 地址 + 缓存余额；不持有任何密钥材料，无法签名。

方法路由处理器
POST/wallet/accountsCreateAccount（按 xpub + 元数据登记账户）
GET/wallet/accountsListAccounts
DELETE/wallet/accounts/{id}DeleteAccount
GET/wallet/accounts/{id}/balanceBalance（经公共索引器）
POST/wallet/accounts/{id}/addressesAddAddress
GET/wallet/accounts/{id}/addressesListAddresses

余额来自 balance_provider.go → mempool.space（BTC）/ publicnode RPC（ETH）。服务端是便利索引器，从不是托管方。

10 — iOS 集成

local-first，无服务端往返

iOS app 是 local-first（本地优先） 的，不使用 Go 钱包 API。APIClient 在 iOS 上是死代码（未接入登录流；金库本就是 Keychain seed + SwiftData，完全在设备上）。仅为取一个余额而重建一套缺席的认证流是净负收益，因此 iOS 钱包客户端派生，并直连同一组公共索引器（WalletBalanceService：mempool.space / publicnode）。这比 web 路径的零知识更强 —— 地址列表从不离开设备到自家服务器 —— 且与 local-first 金库一致。

持久化（WalletAccountStore，UserDefaults）只存公开账户描述符（币种 / 网络 / 脚本类型 / 索引 / 标签）—— 无密钥、无地址。收款地址在金库解锁时由内存中的种子实时重新派生，于是静态落盘的足迹不含任何敏感物。
