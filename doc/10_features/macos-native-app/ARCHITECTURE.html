Auth Box for Mac
一个用指纹把关的本地凭据中枢

把三个分散的凭据面融合进一个原生 macOS app（应用程序）：密码 Vault（保险库）、70+ AI provider（服务商）密钥中枢、AI agent（智能体）授权管理——全部由 Touch ID（指纹认证）+ Secure Enclave（安全隔区）+ Keychain（钥匙串）在硬件层把关。

复用 AuthBoxCrypto（已支持 macOS 14） 原生 SwiftUI（非 Tauri / 非 Catalyst） 把关 Touch ID = step_up 策略后端 修复 AI-Fleet git 密钥泄露类问题

1 · 为什么要做它

本地的三个凭据面目前是割裂且部分不安全的。一个 native（原生）Mac app 把它们统一到一个硬件把关的 broker（代理中枢）背后。

① 密码

Auth Box Vault 已有 web 和 iOS 客户端，但缺一个一流的 Mac 原生客户端——Layer 3（便利层）此前只把桌面端标记为 Tauri（计划）。

② AI provider 密钥

web 端有 provider 中枢，但在开发者的 Mac 上密钥会泄漏进 git 跟踪的配置文件。2026-06-01 的舰队审计在 gemini-api-config.json、pm2 env dump（环境快照）、探针脚本里发现了真实的 provider 密钥——这正是本地 Keychain broker 能消除的失败模式。

③ Agent 授权

哪个 AI agent 能用哪个凭据、在什么策略下，由 MCP Gateway（网关）策略引擎执行；但 step-up（升级认证）缺一个强本地因子——没有硬件级的 human-in-the-loop（人工介入）门。

关键洞察

Mac 是唯一一台已经具备正确原语的设备：Touch ID（LocalAuthentication）、Keychain、Secure Enclave。原生 macOS app 把三个面统一到一个硬件把关的 broker 之后。

2 · 架构决策记录（ADR）

决策不是凭空选型——真实代码已经决定了它。

ADR-001 — 原生 SwiftUI macOS，不用 Tauri，也不用 Mac Catalyst
决定：新建一个共享 AuthBoxCrypto 的多平台 SwiftUI 目标 apps/macos，输出 Mac 原生 UI（主窗口 + 菜单栏）。
  • AuthBoxCrypto/Package.swift 已声明 platforms: [.iOS(.v17), .macOS(.v14)]，crypto 核心（Argon2id / SRP-6a / HKDF / AES-GCM / BIP-39）已跨平台，复用成本 ≈ 0。
  • 密码管理器是安全产品：Tauri / Electron 的 web 运行时带来的额外攻击面不可接受，而原生方案给出一流的 Secure Enclave 密钥包裹 + Keychain ACL（访问控制列表）+ App Sandbox（沙箱）+ Touch ID。
  • Mac Catalyst 会产出手机形态的 app——对一个要像 1Password / Keychain Access 那样的菜单栏 broker 来说，是错误的 UX。
ADR-002 — Touch ID 是现有 step_up 策略的后端
决定：不发明新的认证概念。
MCP 策略引擎已把 step_up 定义为标准策略类型（见 postmortem PM-20260531-002）。macOS app 通过 LAContext.evaluatePolicy 实现 step_up。Touch ID 是接到已存在扩展点上的后端，不是新增的面。
ADR-003 — 处处 deny-by-default（把 PM-002 教训烘焙进去）
决定：策略评估 fail-closed（失败即关闭）。
未知策略类型 → 拒绝；缺少 scoped 必填属性 → 拒绝；要求 step_up 但生物识别不可用 → 拒绝（绝不静默降级）。与 PM-002 在 Go/TS 侧的修复对齐，让三个引擎（TS MCP、Go API、Swift broker）契约一致。
ADR-004 — 密钥只进 Keychain + Secure Enclave，绝不进 app bundle 或 git
决定：明文凭据与 Vault 主密钥永不以明文落盘、永不进 app 包或 git。
Vault 主密钥由一个常驻 Secure Enclave 的密钥包裹，仅在 Touch ID 之后释放。这是 AI-Fleet 密钥泄露类问题的结构性修复。
已放弃的备选
Tauri 桌面端（web 攻击面）· Mac Catalyst（错误 UX）· 新写一套 crypto（违反复用，重新引入 ios:crypto-vectors 测试要防的跨实现分歧）

3 · 融合的三个域

3.1 密码 Vault

复用 AuthBoxCrypto：助记词（BIP-39，24 词）→ 主密钥（Argon2id）→ Vault 密钥（HKDF）→ AES-GCM 逐项加密；确定性密码派生（seed + site → password）支持「空保险库」模式。本地用 SwiftData 仅存密文 blob + 元数据；Vault 密钥仅在解锁期间驻留内存，静止时由 Secure Enclave 密钥包裹。可选经现有 Go API 同步（SRP-6a 认证、零知识 blob），同步是 Layer-2 可选项，离线完全可用。

3.2 AI Provider 中枢

CredentialCatalog（Swift）由 credential-catalog.ts 代码生成（单一事实源，70+ provider / 15 类）——生成而非手抄，杜绝目录漂移。支持 .env 拖拽导入（解析→按 EnvPattern 分类到 provider→预览→存为带 categoryId/providerId 标签的 Vault 项）与 凭据健康检查（移植 credential-health.ts，一键校验密钥是否仍有效）。每个 provider 密钥都是一等 Vault 项，因此继承加密、同步与授权策略。

3.3 授权 / Agent 委派 broker

本地 host 一个 MCP Gateway 在 ws://127.0.0.1:19876（仅环回）。AI agent 连入，按 itemId（服务名）+ action 请求凭据，Swift 策略引擎按五原语评估：
  • Capability（能力）：agent 被允许请求什么
  • Intent（意图）：具体请求（item + action + 上下文）
  • Policy（策略）：item_scope | action_perm | rate_limit | time_window | step_up
  • Effect（效果）：按策略的释放或拒绝
  • Fact（事实）：不可篡改的审计记录
step_up → 一次 macOS Touch ID 提示 + 菜单栏 consent（同意）卡片：「Claude 想用 OpenAI 密钥执行 proxy.chat —— 允许一次 / 拒绝」。Deny-by-default。这就是 AI-Fleet 的修复：gemini-proxy 不再从 git 跟踪的配置读密钥，而是向 broker 请求，由 broker 在 Touch ID 后按策略释放并记录访问。

4 · macOS 认证与密钥架构

硬件信任链：指纹 → 安全隔区密钥 → 内存中主密钥 → 逐项密钥 → 按策略释放明文。

Touch ID LocalAuthentication · evaluatePolicy(.deviceOwnerAuthenticationWithBiometrics)
▼
Secure Enclave 密钥 kSecAttrTokenIDSecureEnclave · 访问控制 .biometryCurrentSet + .privateKeyUsage
▼ 解包
Vault 主密钥 仅解锁期间驻留内存；锁定/休眠时清零
▼ HKDF
逐项 AES-GCM 密钥 解密 → 明文凭据（按策略释放）
  • Keychain 存放 Secure-Enclave 包裹的 Vault 密钥，访问控制要求 biometryCurrentSet——重新录入指纹即失效（抗胁迫）。
  • 自动锁定：休眠、屏保、可配置空闲后；清零内存主密钥。
  • App Sandbox + Hardened Runtime（强化运行时）+ 公证（notarization）：凭据 broker 的必备项，约束进程被攻破后的爆炸半径。
  • keychain-access-groups + app-group group.com.authbox.shared：让未来的 macOS AutoFill（自动填充）扩展共享 Vault，与 iOS 现有 entitlements（权限声明）镜像一致。

5 · 威胁模型（攻击者视角审查摘要）

威胁缓解
恶意软件读取磁盘上的 Vault静止时 Vault 密钥由 Secure Enclave 包裹，落盘的只有密文 blob
进程内存抓取主密钥仅解锁期间在内存；锁定/休眠清零；沙箱隔离
恶意 AI agent 经 MCP仅环回绑定；deny-by-default 策略；step_up Touch ID；逐请求审计
策略枚举漂移 / fail-openSwift 引擎与 TS+Go 契约测试；未知类型 → 拒绝（PM-002）
密钥进 bundle / git结构上不可能——密钥只在 Keychain/Enclave，绝不进 app 发布的文件
被胁迫重录指纹biometryCurrentSet 在录入变更时使包裹密钥失效
重放 / 过宽授权rate_limit + time_window + item_scope 策略；consent 默认「允许一次」

发布前必经一次 /security 攻击者视角审查 SubAgent（子代理）门禁（见第 6 节 P5）。
